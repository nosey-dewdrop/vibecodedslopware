BOLUM 3 (localhost nedir, neden sadece sende calisiyor)
- BU BOLUMUN TAMAMI ESKIDE VAR VE CANLIDA 8 SATIR. Eski dosyada 420 satirlik, RFC
  seviyesinde bir DERINLIK bolumu var. Kalemler:
  · RFC 6761 (Cheshire & Krochmal, Sub 2013, doi:10.17487/RFC6761) localhost'u
    special-use domain name yapar. RFC 2606 (Haz 1999) .localhost'u rezerve TLD listesine
    koyar. localhost adini hicbir registrar satamaz — protokol seviyesinde yasakli.
  · RFC 1122 (Eki 1989) §3.2.1.3(g) loopback adresini tanimlar, ismini degil.
  · RFC 990 (Kas 1986) asil atama: "The class A network number 127 is assigned the
    'loopback' function." /8 secilmedi — 1986'da CIDR yoktu (CIDR 1993, RFC 1518/1519),
    adres alani classful idi. "Neden /8?" sorusunun gercek cevabi bu.
  · IPv4'te loopback'e ayrilan adres sayisi 16.777.216, IPv6'da 1. "IETF ayni hatayi iki
    kere yapmadi."
  · Bir IETF Internet-Draft 127/8'i 65.536 adrese (127.0.0.0/16) daraltmayi oneriyor.
  · IANA kaydinda 127/8 icin "False [with exceptions noted in RFC8029 and RFC5884]" —
    MPLS LSP Ping ve MPLS-BFD 127/8'i kablo uzerinde kasitli kullaniyor.
  · RFC 4291 §2.5.3 (::1 loopback) · RFC 6724 default policy table'da ::1/128 precedence 50
    -> localhost'a baglanan Node client once ::1'i deniyor.
  · RFC 6335 §6 port araliklari: System 0-1023, User 1024-49151, Dynamic/Ephemeral
    49152-65535 (never assigned). 5173 ve 4200 icin IANA kaydi YOK.
  · Port alani 16 bit = 0-65535, 65536 deger. Baglantiyi benzersiz kilan 4'lu tuple.
  · RFC 9293 §3.5.2 — connection refused'in resmi tanimi: dinleyen socket yoksa RST.
  · RFC 1918 private address space (10/8, 172.16/12, 192.168/16) + RFC 3927 link-local
    169.254.0.0/16 — "Wi-Fi bagli ama internet yok"un sebebi.
  · 0.0.0.0'in IANA'da iki kaydi: 0.0.0.0/8 "This network" (RFC 791 §3.2) ve 0.0.0.0/32
    "This host on this network" (RFC 1122 §3.2.1.3). "0.0.0.0 = tum arayuzler" socket
    API'sinin yerel konvansiyonu, IP protokolunde boyle bir anlam yok.
  · /etc/hosts tarihi: HOSTS.TXT (SRI-NIC), DNS RFC 1034/1035 (1987) onu degistirdi.
  · TLS 1.3 RFC 8446, TCP RFC 9293 ile 8 adimli tam istek hayat dongusu.
  · --host flag'inin gercekte ne yaptigi: sadece listen()'a verilen bind adresini
    degistirir. vite --host = 0.0.0.0. webpack-dev-server ayrica local-ip / local-ipv4 /
    local-ipv6 ozel degerlerini destekliyor; Vite'da bu YOK.
  · Tunel araclari (ngrok, cloudflared) tam olarak ne yapiyor.
- DAMLA OLCUMU — bu makinede yapildi (macOS Darwin 24.2.0, Node v26.5.0):
  · macOS/BSD'de 127.0.0.1 disindaki loopback adresleri OLU: ping 127.0.0.2 ->
    "1 packets transmitted, 0 packets received, 100.0% packet loss". Linux'ta 127.7.7.7
    ping atar ve bind edilebilir (systemd-resolved 127.0.0.53'te bu yuzden oturabiliyor).
  · lo0 satiri: "lo0: flags=8049<UP,LOOPBACK,RUNNING,MULTICAST> mtu 16384" —
    macOS MTU 16384, Linux 65536. Ayni kavram, farkli sayi.
  · Iki hata yan yana olculdu: nc -vz 127.0.0.1 9 -> "Connection refused";
    nc -vz -w 3 192.0.2.1 81 -> "Operation timed out". Refused vs timeout farki.
  · /etc/hosts icerigi ve "Do not change this entry" yorumu.
